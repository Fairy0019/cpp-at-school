# 下一步计划

> 状态：规划稿，尚未实现。  
> 本文记录《地下王都》下一阶段的功能、场景、敌人与世界观扩展方向，后续可以继续追加。

## 1. 见闻系统

在营地 / 状态菜单中新增「见闻」入口，用来存放玩家收集到的信息。

### 记录内容

- 主线线索与已经发现的历史记录
- NPC 对话中提到的传闻、人物和地点
- 古物、石板上的文字与解读
- 已经遭遇的敌人、首领和区域
- 已经确认的结局与关键设定

### 交互方式

- 按分类浏览，未读条目显示「新」标记
- 条目详情包含来源、相关人物和关联线索
- 古文字条目分为「原文」和「译文」两种状态：未解读时只显示原文，解读后解锁译文
- 见闻解锁后永久保留，并随身份牌存档
- 可以扩展现有的 `story_progress.sav`，也可以新增独立的见闻存档，具体待定

## 2. 城门后的地面枢纽

进入城门后不再直接进入营地，而是先进入地面枢纽，提供多个去处：

| 地点 | 功能 | 说明 |
| --- | --- | --- |
| 商店 | 买卖物品 | 现有商店独立成入口；商人库存中可能出现古物和石板 |
| 废墟（营地） | 休息、存档、整理背包、交谈 | 现有营地功能迁移到这里 |
| 酒馆（旅店） | 付费休息、打听消息、NPC 对话 | 新场景，可作为传闻和支线的集散地 |
| 城（高塔） | 进入高塔 | 高塔共五层，顶层为征服骑士 |

- 玩家可以在枢纽中自由选择去处，也可以返回城门。
- 高塔与地下的开放顺序、是否需要剧情解锁，待定。

## 3. 高塔五层与地下十五层

### 空间结构

| 区域 | 层数 | 内容 | 首领 / 关键角色 |
| --- | --- | --- | --- |
| 地面高塔 | 5 层 | 向上探索的城塔 | 顶层：征服骑士 |
| 地下·前王国 | 地下 1—5 层 | 因地裂陷入地下的前王国 | — |
| 地下·古国 | 地下 6—15 层 | 被整体掩埋的古国 | 巡游骑士 |
| 连通缺口 | 前王国与古国之间 | 新旧两国在地下的连通处 | 缺口守卫骑士 |
| 地心炉 | 地下最深处 | 古国核心 / 炉心 | 地心炉守卫骑士 |

### 四骑士分布

- **征服骑士**：高塔顶层。
- **缺口守卫骑士**：镇守新旧王国之间的连通缺口，玩家可以从缺口处遇见。
- **巡游骑士**：在地下 6—15 层的古国区域巡游，遭遇位置不固定。
- **地心炉守卫骑士**：守在地心炉。

> 除「征服骑士」外，其余三个名称暂为工作名，正式名称待定。  
> 现有「封存骑士」与地心炉守卫骑士是合并、改名还是作为前置形态，待定。

## 5. 对话、古物与考古者

### 门卫对话

- 机械门卫在登记、查验身份之外增加「交谈」。
- 对话随主线进度变化，可以透露城门、灾害、高塔和地下的传闻。
- 部分对话首次触发时写入「见闻」。

### 商人对话与古物

- 商店增加「交谈」选项，可以打听货源、传闻和考古者。
- 商人每次刷新库存时，有概率出现古物或石板。
- 古物和石板可以获取信息：购买后阅读 / 鉴定，解锁「见闻」条目。
- 石板文字直接以希伯来文字符显示，游戏内设定为古国文字；未解读时只显示原文。
- 只有考古者或四骑士能读懂；与他们对话后解锁译文。
- 古物出现概率、价格和是否占用背包容量，待定。

### 考古者 NPC（后续）

- 新增一名考古者 NPC，负责鉴定古物、翻译石板、补充古国历史。
- 出现位置可以在酒馆、营地或遗迹中，具体待定。
- 与考古者多次交谈，可以逐步解锁古国、四骑士和地心炉的背景。

## 6. 世界观调整：火山灰与面具

将「脸不可见 / 身份牌代替脸」的设定改为：

- 地震引发火山爆发，火山灰极多，烟雾长期笼罩城市与地下入口。
- 居民必须戴面具才能外出，面部被面具、灰烬和烟雾遮蔽。
- 身份牌制度可以保留，用于城门登记与存档，但不再是「以牌代脸」的唯一解释。
- 角色文字形象、NPC 描述和场景氛围需要体现面具、护目镜、兜帽、灰烬等元素。
- 火山爆发可以与现有的火灾 / 地震灾害联动，作为三灾加剧后的表现。

实现时需要同步修改现有 README 中关于「身份牌代替脸」的段落，避免设定冲突。

## 7. 非剧情内容与画面表现

这一节关注战斗演出、过场 CG 和渲染管线，不改变主线剧情，但直接影响游戏的完成度和观感。

### 7.1 攻击动作

当前战斗以文字结果为主，下一阶段给攻击、魔法、大招和受击加入短促的动作演出。

**普通攻击**

1. 选择指令后，角色先向后蓄力 1—2 格。
2. 角色向前突进 2—4 格，武器字符向目标挥动。
3. 命中时目标闪白 / 闪红，画面轻微震动，伤害数字上浮。
4. 角色回到待机位，战斗日志再输出结果。

**其他动作**

| 动作 | 表现 |
| --- | --- |
| 魔法 | 施法者抬手 / 发光，字符弹道飞向目标，命中后爆开；MP 条同步下降 |
| 大招 | 全屏闪烁 + 震动，分段显示多段伤害，充能条清空 |
| 防御 | 角色下蹲或出现护盾字符，受击时伤害数字变小 |
| 敌人攻击 | 使用同一套蓄力 / 突进 / 命中逻辑，首领可以有专属动作 |
| 使用物品 | 角色举起药水，回复数字上浮，HP / MP 条回涨 |

- 单次动作控制在 0.5—1.5 秒，连续战斗时不能太拖沓。
- 支持按键跳过；非交互输出时直接显示最终结果。
- 伤害数字建议区分普通、暴击、魔法、回复，例如 `-12`、`暴击 -18`、`+20`。
- 角色和怪物沿用现有文字形象，额外准备 2—3 个动作帧（蓄力、出手、受击）。
- 战斗动画只重绘战斗舞台区域，不整屏刷新，避免闪烁。

### 7.2 过场 CG：文字像素画

用字符当作像素点绘制过场画面，保持项目现有的纯文字风格。

- 每个单元格是一个字符：`█`、`▓`、`▒`、`░` 表示不同明暗，空格表示透明。
- 使用 ANSI 颜色给不同图层着色；画面分辨率建议控制在 100×30 左右，保证在 105 列画框和 120×44 控制台内完整显示。
- 先做静态 CG，再逐步增加 2—3 帧的环境动画：火山灰飘落、火星、烟雾、火把闪烁、骑士眼部的光。
- 建议的 CG 节点：
  - 序章灾难 / 倒悬王都
  - 城门与机械门卫
  - 第一次进入地裂
  - 高塔顶层与征服骑士
  - 新旧王国连通缺口
  - 地心炉与地心炉守卫骑士
  - 四种结局
- 播放方式：淡入 / 扫描线展开 → 显示完整画面 → 底部字幕逐字出现 → 等待按键 / 自动继续。
- CG 必须先绘制完整画面，再输出字幕，避免出现「画面还没画完就开始打字」的问题。
- 已解锁的 CG 可以考虑放进「见闻」里回放，作为收集要素。

### 7.3 画面呈现优化

当前 `Frame::renderTypewriter()` 的顺序是：先输出顶部边框，再逐行逐字打印文字，最后才输出底部边框。因此打字过程中下半画框是缺失的，看起来像画面在逐行「长出来」。

建议改为两阶段渲染：

1. **先画完整画框**：顶部边框、上下留白、所有文字行的占位空格、分隔线和底部边框一次性输出。
2. **再定位打字**：把光标移回需要逐字显示的行，在固定列位置覆盖文字；边框和底边始终保持完整。
3. 光标定位可以使用 ANSI 序列 `\x1b[{行};{列}H`；Windows 控制台已经在 `setupConsole()` 中开启虚拟终端处理，也可以回退到 `SetConsoleCursorPosition`。
4. 动画期间隐藏光标，结束后恢复；每帧统一刷新，减少闪烁。
5. 输出被重定向或非交互运行时，仍然直接打印完整文本，不做光标移动。

在此基础上可以继续做：

- **屏幕缓冲 / 差分刷新**：先把一屏内容组合成 `vector<string>`，和上一帧比较，只重写变化的行或区域。
- **局部重绘**：战斗动作只重绘角色、怪物、血条和伤害数字所在区域，不整屏清空。
- **打字范围**：只让剧情、对白和战斗日志逐字显示；菜单、状态栏、HP / MP 条、提示行立即出现。
- **跳过**：按 Enter / Space 立即完成当前打字或动画。
- **减少清屏**：场景切换时清屏，普通回合和动画使用光标归位 + 覆盖输出；每行补满宽度，避免残留字符。
- **兼容小窗口**：画框、CG 和动画都按当前控制台尺寸做降级；放不下时优先保证边框和操作提示可见。
- **跨平台**：如果继续发布 Linux 版，可以给 POSIX 终端增加 `isatty` 检测和 ANSI 支持，让颜色、光标定位和动画在 Linux 下也能工作。

## 8. 与现有内容的关系

- 现有的八幕线索、四种结局和三灾系统可以保留，作为主线骨架；新区域用于扩展中间流程。
- 现有八幕区域与新高塔 / 地下结构的对应关系待定，也可以先把新层数作为八幕之外的扩展内容。
- 现有营地拆分为地面枢纽中的「废墟（营地）」，商店独立成入口。
- 现有「封存骑士」需要与四骑士体系重新对齐，具体方案待定。
- 「见闻」的解锁进度可以并入现有剧情存档，避免增加过多存档文件。

## 9. 建议实施顺序

1. 先修渲染管线：完整画框 + 定位打字，再考虑屏幕缓冲 / 差分刷新
2. 见闻框架 + 地面枢纽（商店、废墟、酒馆、高塔入口）
3. 高塔 5 层 + 地下 15 层的空间结构和四骑士分布
4. 四种敌人 + 门卫 / 商人对话 + 古物 / 石板 + 考古者 NPC
5. 攻击动作 + 过场 CG，可随战斗和剧情节点逐步加入
6. 面具与火山灰设定落地，统一修改文档和美术描述
