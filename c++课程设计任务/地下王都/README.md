# 地下王都

C++ 课程设计项目，主题来自《设计起步稿.md》。当前是**可运行剧情版**，流程为：

```text
标题（只有「沉 没 王 都」）→ 序章：灾难 / 倒悬王都 / 遗失证明
→ 城门外荒路 → 机械门卫：临时身份牌 / 读档后梦醒
→ 城内营地（状态 / 背包 / 商店 / 交谈 / 休息）
→ 进入区域 → 三段赶路（三灾随时发生）→ 遭遇战
→ 击败区域敌人 → 发现一段旧记录 → 奖励房间（宝箱 / 宝箱怪）→ 返程
→ 八段线索后进入核心 → 封存骑士 → 四结局
```

界面采用画面框 + 彩色状态条 + 文字角色 + 城门场景 + 商店场景 + 赶路场景 + 战斗日志，每回合清屏重绘。所有场景统一使用 105 列 × 34 行的放大画框（内容区至少 32 行），并在窗口内自动增加上下留白；启动时会尝试把控制台调整到 120×44。角色文字画、怪物文字画保持原尺寸，只扩大画面和分区。主角、怪物、商人、灰袍幸存者和机械门卫都是由文字组成的形象。主角的头是「人」，身体是「旅」，右手显示「拳头」或当前武器名；护甲决定头和身体的颜色，武器决定武器名字的颜色，四肢固定不变。

```text
    人
   /旅\  剑
    |  短
   / \
```

没有装备武器时，右侧显示「拳头」；装备短剑显示「短剑」，装备铁剑显示「铁剑」。

## 开场与身份牌

沉没王都在雪灾、地震与火灾后覆灭。入口处的机械门卫属于旧王都遗留设施，只按残存程序执行登记与放行。主角在灾害中丢失了旧身份证明，门卫只能发给一张临时身份牌；它无法识别主角的血脉，也不知道地心炉或灾难的真相。身份牌就是存档文件 `identity.sav`，生成在程序启动目录；`run.bat` 会先切换到项目根目录。

- 第一次游戏：机械门卫检测不到身份牌，要求登记名字、性别和物种，然后写入临时身份牌
- 已经登记：进城时出示临时身份牌，读取存档，继续上一次的进度
- 临时身份牌损坏：门卫会提示“牌子坏了”，可以重新登记
- 营地每次行动后自动存档，离开营地时再存档一次
- 剧情线索进度另存于 `story_progress.sav`，与角色姓名关联；记录已发现的线索数和最终结局，重新登记身份会从头开始

## 故事主线

主角在一次异常灾害中受伤后，开始梦见地下的王都，并被一阵无法解释的回声牵引。醒来时旧身份证明已经遗失，门卫只能给他一张临时身份牌。探索中逐步发现：三灾是地心炉失稳造成的非周期性灾难；地心炉由数百年前旧王朝的国王发明，最终也由他亲手熄灭。新王国并不知道地心炉的存在。主角后来确认自己是那位国王的后裔，血脉只是地心炉封存失效时发出的求援信号，不是必须服从的命令。

城里的幸存者用身份牌代替脸，假身份、抢劫和失踪都没人过问。这是灾后秩序崩溃后的表层社会，真正的地心炉真相埋在地下。营地里的灰袍幸存者会随线索进度给出不同传闻，但他掌握的不是答案。

三灾不只在档案里：赶路和战斗中都会随机发生，没有固定周期，强度随剧情进度上升。赶路中的天灾最多把你压到 1 HP，不会直接死亡；战斗中的天灾会同时伤害双方，可能直接结束战斗。

游戏按八幕推进，每幕在区域尽头发现一段旧记录：

| 线索 | 区域 | 发现 |
| --- | --- | --- |
| 1 | 裂缝前厅 | 地底召唤、缺角的炉形记号 |
| 2 | 冻结粮仓 | 盛夏雪灾，发生时间没有周期 |
| 3 | 观测站 | 所有震中都指向地下核心 |
| 4 | 熔毁工坊 | 地心炉、热量与压力失控 |
| 5 | 王室档案馆 | 国王亲自停炉，随后离开王都 |
| 6 | 沉没街区 | 三灾同源，新王国对此一无所知 |
| 7 | 骑士回廊 | 四守护单元与“天启四骑士”传说 |
| 8 | 核心门厅 | 旧王朝签名、血脉访问权限 |

每次探索并击败区域敌人后才会发现下一段记录；集齐八段后核心开启，门口会先与封存骑士战斗。封存骑士是四守护单元中最后仍在执行命令的一尊；另外三尊已经停摆，留作后续扩展。进入核心后可选择熄灭、稳定、摧毁炉心或拒绝介入。剧情进度保存在 `story_progress.sav`。

### 三灾事件

- **雪灾**：反季节暴雪，损失 HP。
- **地震**：地面倾斜、碎石落下，损失 HP。
- **火灾**：热浪与火焰，损失 HP 和 MP。
- 赶路时每段路都可能触发；如果前面没有触发，靠近区域尽头前会再判定一次，保证每次探索至少经历一次天灾。
- 战斗中每 2—4 回合触发一次，同时伤害玩家和怪物，强度和频率随剧情进度上升。
- 三灾没有固定顺序，也没有可靠周期。

## 已实现

### 开场与身份牌

- 开场画面简化为只有「沉 没 王 都」
- 序章分三页：不合时令的灾难、倒悬王都的梦、醒来后遗失旧身份证明
- 城门外荒路：`[1] 进城`、`[0] 离开游戏`
- 残破的机械门卫：由「我 / 是 / 人 / 机」文字组成的旧王都设施
- 门卫只发行临时身份牌，无法核实旧身份，也不识别血脉
- 没有身份牌时，门卫要求登记名字（最多 10 个显示列）、性别和物种，写入 `identity.sav`
- 性别预设：男 / 女 / 不明，也支持自定义
- 物种预设：人类 / 精灵 / 兽人 / 机械 / 亡灵，也支持自定义
- 已有身份牌时，门卫显示姓名、性别、物种、等级、金币，出示后读取存档进城
- 读档后不再直接跳回营地，而是先播放“梦 · 沉没的王都 / 醒来 · 营地的火 / 回忆 · 来时的路”三页梦醒过场，暗示主角并非完全出于自己的意愿来到这里
- 剧情、门卫对话、营地交谈、商店对话、遭遇旁白和结算文字使用逐字打字效果；菜单、状态栏和战斗数值仍然即时显示
- 临时身份牌损坏 / 字段缺失时，提示“牌子坏了”，允许重新登记
- 城市表层保留灾后氛围：看不清脸的人影、假身份、抢劫和失踪都没人过问
- 营地新增灰袍幸存者：可以询问灾难、遗迹和四骑士，回答随线索进度变化
- 八幕区域依次为裂缝前厅、冻结粮仓、观测站、熔毁工坊、王室档案馆、沉没街区、骑士回廊、核心门厅
- 每次探索并击败区域敌人后才发现下一段记录，不再一进城就自动弹出
- 第 8 段线索后核心开启；核心门前与封存骑士战斗，胜利后才能进入终幕
- 终幕包含旧国王留言、四选一核心抉择，以及每个结局各自的两页尾声
- 每次探索胜利并发现线索后会进入奖励房间：可以打开宝箱，也可以直接离开
- 宝箱有 30% 概率是宝箱怪；普通宝箱给金币 / 药水 / 旧王都装备，宝箱怪会进入独立战斗
- 营地商店不是每次都有：有游商时商品齐全、价格固定；没有游商时只能和拾荒者交易，商品 3—5 件、价格在 0.75—1.4 倍之间浮动
- 新身份自带 20 金币和两瓶红药水
- 存档包含姓名、性别、物种、等级、经验、HP / MP、金币、背包物品、武器、防具、饰品和大招充能
- 营地每次行动后自动存档，离开营地时再存档一次
- 三灾会在赶路和战斗中随机发生：赶路最多压到 1 HP，战斗会同时伤害双方，可能直接结束战斗

### 基础机制

- 抽象基类 `Character` + 纯虚函数 `takeTurn()`，`Player` 和 `Monster` 通过基类接口行动
- 玩家属性：HP / MP / ATK / DEF / EXP / 金币 / 等级
- 普通怪物：遗迹鼠、水/火史莱姆、哥布林，遭遇时随机选择
- 首领怪物：封存骑士，属性随玩家等级成长；每三回合使用一次封存冲击，击败后掉落「封存核心」
- 宝箱怪：奖励房间打开宝箱时 30% 触发，属性随玩家等级成长；每三回合用箱盖猛合，击败后掉落「宝箱碎片」并追加宝箱战利品
- 史莱姆有水和火两种属性：水史莱姆高防低速，火史莱姆高攻低防
- 史莱姆 50% 概率掉落「史莱姆粘液」，可卖给商人
- 哥布林 40% 概率带着一件抢来的装备，击杀后 30% 概率掉落该装备（整体约 12%）
- 随机伤害浮动（±15%）与 30% 概率暴击（暴击伤害 50%，即 ×1.5）
- HP 归零判定死亡 / 战败，扣血不会出现负值
- 战斗胜利获得经验与金币，经验达到阈值自动升级
- 营地休息、非法输入重试
- Windows 控制台 UTF-8 中文显示，支持 ANSI 颜色时自动启用

### 商店

- 商人形象：头部为「人」，身体为「商」，站在柜台后
- 八种商品：红药水、蓝药水、短剑、铁剑、皮甲、铁甲、铜戒、护符
- 游商不是每次都在：每次探索或休息后重新判定，约 50% 概率出现；没有游商时菜单显示“与人交易”
- 拾荒者交易：商品从八种里随机抽 3—5 件，价格在基础价的 0.75—1.4 倍之间浮动，使用灰袍幸存者形象
- `Shop(int itemCount, double priceScale)` 用于生成不同库存和价格；默认 `Shop()` 仍是八件齐全、价格不变
- 购买：按编号选择商品，检查金币与背包容量，扣款后把物品复制进背包
- 出售：按编号出售背包物品，按售价的一半回收金币
- 商品原型与背包物品分离，购买时通过 `clone()` 复制，不会把商店货架买空
- `Shop::operator[]` 支持按整数编号和按名称取商品，越界 / 找不到时抛出 `std::out_of_range`
- 金币使用 `Wallet` 类封装，重载 `+=`、`-=`、`+`、`-`，购买时实际调用 `wallet -= price`

### 背包与装备

- 背包容量 8 格，显示金币、容量、装备和物品说明
- 消耗品（红药水 / 蓝药水）可以在营地、商店和战斗中使用
- 装备可以穿戴、卸下、替换，旧装备自动放回背包
- 装备栏分为武器、防具、饰品三类；饰品同样提供攻击 / 防御加成
- 武器加成攻击、防具加成防御，饰品可以同时加成攻击和防御；`Player::getAttack()` / `getDefense()` 在基础属性上叠加全部装备
- 状态界面显示 `攻击   总值  ( + 加成 )`、`防御   总值  ( + 加成 )`，并显示基础暴击率 30%、暴击伤害 50%（×1.5）
- 在背包中使用装备会自动穿到对应部位；战斗中只能使用消耗品，不能换装备
- `Inventory::operator+` 和 `Player::operator+` 都可以把物品加入背包，返回自身支持链式调用

### 战斗中的背包、魔法与大招

- 战斗菜单按 `3` 打开战斗背包：显示所有物品、HP/MP 和金币
- 选择消耗品会实际回复 HP / MP，并消耗一个回合
- 选择装备会提示“战斗中不能更换装备”，不消耗回合
- 魔法攻击：消耗 4 点 MP，无视防御，造成魔法伤害并给大招充能 +1
- 大招：需要 3 格充能，消耗全部充能，造成 3 倍攻击的无视防御伤害
- 只有魔法攻击能增加充能；普通攻击、防御、物品、逃跑都不充能
- 充能会跨战斗保留，并写入身份牌存档
- 蓝药水可以恢复 MP，为魔法提供续航
- 战斗界面压缩为：双人立绘 + HP/MP/充能 + 2 条战斗日志 + 单行操作栏

### 画面

- 封面只保留「沉  没  王  都」，外层双线框内有残破内框、裂纹、旧分隔线和「古 / 城 / 咒 / 罪 / 墟」纹样
- 城门外荒路、机械门卫登记处、身份牌卡片
- 所有场景统一 105 列 × 34 行大画框：`Frame` 负责边框、内边距、居中、分栏、分隔线、自动换行和纵向留白
- `Frame` 默认最小内容高度 32 行，内容不足时自动在上下补空白；角色文字画仍按原尺寸居中，不会被放大或重绘
- 启动时尝试把 Windows 控制台调整为 120×44，保证 105 列画框和提示行能完整显示；调整失败时保持原窗口尺寸
- 中文显示宽度计算：全角字符按 2 列、ANSI 转义按 0 列，框线严格对齐
- 打字机效果：`UI::typeText()` 按 UTF-8 字符逐个输出，ANSI 颜色序列即时跳过，标点自动加长停顿；输出重定向时直接打印全文，方便测试和保存日志
- 血条 / 魔法条 / 充能条，按比例着色
- 主角文字形象：头「人」、身体「旅」、右手显示「拳头」或当前武器名（短剑 / 铁剑）；护甲改变头和身体颜色，武器改变武器名字颜色，四肢颜色固定
- 主角形象在营地、状态、城门荒路、赶路、战斗中都会出现
- 赶路：区域过场 → 三段走廊 → 区域尽头，主角会逐格向右走
- 遭遇过场：普通怪物随机出现；核心门前固定出现封存骑士，奖励房间可能跳出宝箱怪
- 战斗画面：主角与怪物左右分栏对峙，中间有分隔线；操作栏压缩为单行，顶部会显示当前天灾；首领战标题为「核心回廊 | 守护者战」，宝箱怪为「奖励房间 | 宝箱怪」
- 奖励房间：单独的房间画面，显示宝箱文字画和打开 / 离开选项
- 返程过场：战斗胜利、逃跑或主动返回时，显示主角返回营地的过渡画面

## 编译运行

需要支持 C++17 的 g++（当前环境为 MinGW-w64 GCC 8.1）。

- 双击 `run.bat`：没有编译过就先自动编译，然后启动游戏。建议用它启动，因为它会先切换到项目根目录，身份牌 `identity.sav` 也会保存在这里。
- 双击 `build.bat`：只编译，生成 `build\dungeon.exe`。

也可以在命令行执行：

```bat
g++ -std=c++17 -Wall -Wextra -O2 -finput-charset=UTF-8 -fexec-charset=UTF-8 -o build\dungeon.exe src\*.cpp
build\dungeon.exe
```

## 玩法

开场：

- 标题画面按回车 → 主角在灾害中受伤后开始梦见沉没王都，并被地底回声牵引
- <城门外荒路>
- 荒路：`1` 进城，`0` 离开（这里弹出一行字：不过，你离开了，同样，你与一些神奇的故事也分开了，这似乎是命中注定的）
- 门卫处：
  - 有临时身份牌：`1` 这是我的身份牌（读档），`2` 不，我忘记了自己是谁（重新登记），`0` 返回荒路
  - 没有身份牌 / 临时身份牌损坏：`1` 登记临时身份（名字、性别、物种），`0` 返回荒路
- 读档成功后先播放三页梦醒过场，再回到营地；首次登记则播放进城旁白
- 登记完成后按回车进入城内，自动存档
- 剧情、门卫对话、营地交谈、商店对话和遭遇旁白会逐字出现，按回车继续

营地：

- `1` 查看状态（含武器、防具、攻击、防御）
- `2` 打开背包（使用药水、穿戴 / 卸下装备）
- `3` 商店 / 与人交易：有游商时打开完整商店；没有游商时与拾荒者交易（3—5 件随机货，价格浮动）
- `4` 与灰袍幸存者交谈（灾难 / 遗迹 / 四骑士）
- `5` 进入遗迹（推门过场 → 赶路）；八段线索后变为“进入核心”，通关后变为“回望核心”
- 每次探索并击败区域敌人后才会发现下一段剧情记录；第 8 段后核心开启
- 战斗胜利后会进入奖励房间：`1` 打开宝箱，`0` 离开；宝箱有 30% 概率是宝箱怪
- `6` 休息，恢复 HP / MP
- `0` 离开游戏（自动存档）

商店：

- `1` 购买，再输入商品编号
- `2` 出售，再输入背包物品编号
- `3` 查看背包
- `0` 离开商店

背包：

- `1` 使用 / 装备，再输入物品编号
- `2` 卸下武器
- `3` 卸下防具
- `4` 卸下饰品
- `0` 返回

赶路：

- `1` 继续前进；走到 `3/3` 后变成“靠近木门”（核心门厅为“靠近核心门”）
- `2` 查看状态
- `3` 返回营地

战斗：

- `1` 攻击
- `2` 防御（本回合受到的伤害减半）
- `3` 打开战斗背包，使用消耗品；装备不能在这里更换
- `4` 魔法，消耗 4 MP，无视防御，并给大招充能 +1
- `5` 大招，需要 3 格充能，消耗全部充能，造成 3 倍攻击的无视防御伤害
- `0` 逃跑（70% 成功，失败会挨一次攻击）

充能只会被魔法增加，普通攻击、防御、物品和逃跑都不会充能；充能跨战斗保留并写入存档。

## 设计说明（可写进报告）

- **为什么 `takeTurn()` 是纯虚函数**：玩家和不同怪物的回合行为不同，基类只规定「必须能完成一个回合」这一接口；战斗流程只依赖 `Character&`，不需要知道具体类型。以后增加怪物时只需新增派生类并重写 `takeTurn()`。
- **为什么攻击逻辑放在基类**：伤害浮动、暴击、防御减伤是所有角色共用的规则，放在 `Character::attack()` 中避免重复；`takeTurn()` 决定「这个回合做什么」，两者职责分开。魔法和大招因为要无视防御、读取充能，单独放在 `Player` 中，不把特殊规则塞进普通攻击。
- **魔法与大招的充能规则**：魔法消耗 4 MP、无视防御，并且只在成功施放后增加 1 格充能；大招需要 3 格充能，使用后清空。普通攻击、防御、物品、逃跑都不会充能。充能保存在 `Player` 中并写入存档，所以可以跨战斗积累，形成“用魔法攒大招”的资源循环。
- **玩家形象与装备颜色**：`PlayerSprite` 用 `人`、`旅` 和右手武器文字拼出主角。没有武器时右手写「拳头」，装备后写对应武器名；护甲颜色只作用于头部「人」和身体「旅」，武器颜色只作用于武器文字，四肢始终保持灰色；同一套渲染函数被营地、状态、赶路和战斗复用。
- **封面纹样**：封面完全用文字和盒线绘制，外层双线框、内层残破边框、裂纹、旧分隔线和「古 / 城 / 咒 / 罪 / 墟」纹样共同营造复古、破碎感，没有引入图形库。
- **`Shop::operator[]` 的语义**：重载了两个版本——按整数编号取商品，以及按商品名取商品；内部先检查范围 / 查找名称，失败时抛出 `std::out_of_range`。界面使用编号版本，名称版本保留给后续任务或脚本使用。
- **`Player::operator+` / `Inventory::operator+` 的语义**：向背包添加物品并返回自身，支持 `player + item1 + item2` 这类链式表达。内部用 `unique_ptr` 持有物品，避免多态对象切片。
- **`Wallet` 的运算符重载**：`operator-=` 实现「金币扣除价格」的直观写法，扣除前检查余额并抛出异常保证不会出现负金币；商店购买实际调用 `wallet -= price`。`operator+` / `operator-` 返回值类型的新钱包，便于表达“剩余多少钱”。
- **商品克隆**：`Shop` 保存的是商品原型，购买时调用 `Item::clone()` 复制一份新物品给玩家，因此商店货架不会被移走，背包和商店的物品生命周期互不影响。
- **装备加成**：`Character::getAttack()` / `getDefense()` 设计为虚函数，`Player` 重写后在基础属性上叠加武器、防具、饰品加成。状态界面同时显示总值和 `( + 加成 )`；`Character::attack()` 与 `Player::castMagic()` 使用共同的基础暴击常量（30% 概率，伤害 ×1.5）。
- **身份牌与存档格式**：`identity.sav` 是带版本头的纯文本文件，使用 `key=value` 保存姓名、性别、物种、等级、经验、HP / MP、金币、大招充能，并用 `item=POTION|...`、`item=MATERIAL|...`、`weapon=WEAPON|...`、`armor=ARMOR|...`、`accessory=ACCESSORY|...` 等形式保存多态物品。读取时校验版本、字段、数值范围和背包容量，损坏时返回错误，由门卫允许重新登记，而不是让程序崩溃。
- **读档恢复**：`SaveGame::load()` 先新建一个 1 级 `Player`，再用 `restoreProgress()` 按等级重建基础属性、恢复当前 HP / MP、金币和大招充能，最后放入背包物品并设置装备。这样 `Player` 的成长公式仍然只有一处来源，存档只记录进度，不重复保存派生数值。
- **开场与身份牌流程**：`Game::startFromGate()` 先绘制城门外荒路，再进入门卫登记处。没有存档时依次登记名字、性别、物种并立即写入身份牌；有存档时由门卫展示姓名、性别、物种、等级、金币，确认后读取。进城后每次营地行动和离开营地都会自动存档。
- **剧情与流程分离**：八幕区域和八段线索分别保存在 `AreaInfo` / `StoryClue` 数据表中，`Game` 只负责按 `storyStage_` 取对应文本、控制过场和奖励。以后改剧情或加章节只需要改数据表，不必重写探索流程。
- **剧情进度存档**：`story_progress.sav` 记录角色姓名、已发现的线索数和最终结局。旧版只写姓名的两行存档仍能读取；结局编号用于通关后的营地对话和核心回望，避免“拒绝介入”后仍显示炉心已熄灭。
- **战斗标题与首领标记**：`Monster` 增加虚函数 `getBattleTitle()`，普通怪物返回「地下遗迹 | 遭遇战」，封存骑士和宝箱怪分别返回自己的标题；`isBoss()` 仍用于区分首领逃跑日志，不需要在战斗流程里写 `dynamic_cast` 或具体类型判断。
- **画面层与逻辑层分离**：`Frame` 只负责画框和排版，`Sprites` / `PlayerSprite` 只保存和组合文字素材，`UI` 负责颜色、宽度、输入和延时，`Game` / `Battle` 负责流程和界面内容。
- **放大画框**：`Frame` 默认宽度 105、内容最小高度 32，渲染时把不足的高度平均补到上下留白。角色和怪物文字画仍按原来的行数和列数输出，只是放在更大的画布中央，不会被拉伸。
- **逐字输出**：`Frame::renderTypewriter()` 先立即绘制边框，再对指定文字行调用 `UI::typeText()`；`renderTypewriter(rows)` 允许只打对话框或旁白，不动状态栏、菜单和角色文字画。输出重定向时自动退化为整段打印，避免自动化测试被延时拖慢。
- **读档梦醒**：`Game::showGatekeeper()` 在读档成功时设置 `resumedFromSave_`，`Game::run()` 据此选择“梦醒过场”或首次进城的城市旁白，避免读完档直接瞬移回营地。
- **中文对齐**：`UI::displayWidth()` 按 Unicode 码点计算显示宽度，中文和全角标点算 2 列，ANSI 颜色序列算 0 列；`Frame` 用这个宽度补齐或截断，因此带颜色的血条、角色和边框不会互相挤歪。
- **随机数**：使用 `<random>` 的 `std::mt19937`，以 `std::random_device` 加高精度时钟共同播种，整个程序共享同一静态引擎。MinGW 的 `random_device` 在连续启动的进程中可能给出相同值，混入时钟后能保证每次开局的遭遇、暴击和掉落序列不同。
- **输入健壮性**：`UI::readChoice()` 使用 `getline + stoi`，检查空输入、非数字、尾随字符和越界值，出错时提示并重新输入。
